# Привязка приложения к носителю информации

DoubleCipher - приложение, демонстрирующее привязку приложения к носителю информации. Установщик определяет доступные диски Windows, позволяет выбрать носитель и создаёт контрольные файлы, связанные с серийным номером тома. Приложение использует шифр двойной перестановки для обработки текста.

## Возможности
- просмотр доступных дисков и получение информации о томах через Windows API;
- установка приложения в пользовательский каталог;
- создание контрольных файлов в `files/config`;
- шифрование и расшифрование текста методом двойной перестановки;
- сборка приложения и установщика в `.exe` с помощью PyInstaller.

## Технологии

- **Python 3.10+** - основной язык проекта;
- **Tkinter** - графический интерфейс установщика (входит в стандартную поставку Python для Windows);
- **ctypes / Windows API** - получение списка дисков, типа диска и серийного номера тома;
- **PyInstaller** - сборка исполняемых файлов;
- стандартные модули Python: `os`, `sys`, `shutil`, `json`, `math`, `hashlib`, `time` и др.

Внешние пакеты для запуска исходников приложения не требуются. Для сборки EXE понадобится PyInstaller.

## Структура проекта

```text
DoubleCipher/
├── installer.py             # графический установщик и создание контрольных файлов
├── app/
│   ├── main.py              # консольное меню приложения, ввод ключей и работа с файлами
│   ├── session.py           # проверка контрольных данных и работа с привязкой
│   ├── encrypting.py        # шифрование двойной перестановкой
│   ├── decrypting.py        # обратная перестановка для расшифрования
│   ├── funcs.py             # вспомогательные функции и построение перестановок
│   └── files/
│       ├── encrypt_me.txt   # исходный текст для шифрования
│       └── decrypt_me.txt   # файл для зашифрованного текста
└── README.md
```

Рядом с EXE-файлом приложения создаётся создаётся каталог `files/`:
```text
files/
├── encrypt_me.txt
├── decrypt_me.txt
├── decrypt_res.txt     # создаётся при расшифровании
└── config/
    ├── data.dat
    ├── config.bin
    └── session.dat
```

### Контрольные файлы

- `data.dat` - контрольные данные, преобразованные методом двойной перестановки;
- `config.bin` - двоичные контрольные данные, обработанные XOR-маской и перестановкой байтов;
- `session.dat` - структурированные данные с привязкой, сериализованные в JSON и дополнительно преобразованные реверсом и позиционным XOR.

## Сборка

Установка библиотеки PyInstaller:

```powershell
pip install pyinstaller
```

### 1. Сборка приложения и установщика .exe

```powershell
cd app
pyinstaller --onefile --console --name cipher_app main.py
cd ..
pyinstaller --onefile --noconsole --name installer installer.py
```

Готовые .exe файлы будут находиться в:
- `../dist/installer.exe`
- `../app/dist/cipher_app.exe`

После этого для полноценной работы установщика программы достаточно иметь файлы в таком дереве: 
```text
DoubleCipher/
├── installer.exe
└── app/
    └── cipher_app.exe
```
Остальные файлы проекта для запуска больше не нужны.

## Использование

1. Подготовьте дерево `installer.exe` и папку `app` с `cipher_app.exe`, описанное в пункте выше.
2. Запустите `installer.exe` в Windows.
3. В окне установщика выберите диск, к которому требуется привязать приложение, и запустите установку.
4. После установки запустите `cipher_app.exe` из установленной папки.
5. Для шифрования поместите исходный текст в `files/encrypt_me.txt`, выберите **«Зашифровать»** и введите два ключа. Результат записывается в `files/decrypt_me.txt`.
6. Для расшифрования выберите **«Расшифровать»** и введите те же ключи. Результат записывается в `files/decrypt_res.txt`.

Программа использует длины ключей для построения перестановок. При расшифровании нужно использовать те же ключи и тот же символ заполнения, который применялся при шифровании.

## Ограничения

- Установщик использует Windows API и предназначен для Windows.
- Контрольные файлы и обфускация затрудняют поверхностный просмотр, но не обеспечивают стойкую криптографическую защиту.
- В текущем коде сравнения контрольных данных не прерывают выполнение операций. Для реальной защиты необходимо отдельно реализовать и протестировать отказ в запуске/операции при несовпадении привязки.
